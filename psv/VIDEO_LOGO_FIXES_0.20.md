# 0.20 视频、Logo 和实机错误修复

日期：2026-09-30。

## 实机日志与处理

0.18 在 Logo 后打印 `AVPlayer init failed: -2110126976`，等于 `0x823A0480`。旧代码将有效的高位播放器指针当作负数错误，并跳过 Stop/Close 后卸载模块。改用明确的无效值和错误码命名空间判断，所有有效句柄都先关闭再卸载；初始化失败不会把错误码传给 Close。参考：Vita3K 的 [AVPlayer 实现](https://github.com/Vita3K/Vita3K/blob/master/vita3k/modules/SceAvPlayer/SceAvPlayer.cpp) 明确注明原生返回值是指针，模拟器改用正 UID。这种差异不能通过仅在模拟器检查符号来发现。

用户提供的 0.19 实机日志确认播放器初始化成功 `0x823C7F80`，但没有第一帧便回到标题。0.20 不再以一次 IsActive 真假变化判断播放结束；等待 READY 后读取并启用音视频流，明确调用 Start。尚未收到视频帧及暂时缓冲均继续等待，早停会给出错误。日志保留所有状态计数、首帧尺寸/时间戳、首个 PCM 参数、警告、完成或用户输入跳过原因。参考 [原生 AVPlayer 的流启用与启动流程](https://github.com/SonicMastr/Vita-Media-Player/blob/main/src/avplayer/avplayer.c)。此版本的片头仍需实机复验。

字体读取 835 ms 是启动加载成本。目录创建返回 `0x80010011` 表示目录已经存在，与片头提前结束无关。

## H.264 内置

从用户原 `openning.v` 转为 H.264 Main Level 3.1，保留 800×600、30 fps、2,695 帧；AAC-LC 44.1 kHz 立体声。输出 89.835011 秒、34,911,593 字节，完整解码没有错误，视频与音频时长差约 1.7 ms。SHA-256：`209938e0bcc7790f2a655b9079c67e1859f14581a3faa5305d7fb010a9ee8278`。

编码参数为 CRF 18、slow、2 参考帧、无 B 帧、4 Mbps 峰值、8 Mbps 缓冲、160 kbps AAC 和 faststart。`assets/opening.json` 保存来源及参数，`tools/transcode-opening.py` 可用匹配的原视频重建。VPK 内唯一游戏媒体例外为 `assets/opening.mp4`；其余原始档案继续由玩家放到 `ux0:/data/tenshi/`。桌面参考程序使用原 MPEG-1，不能作为 Vita 硬解证据。

PSV 使用系统 SceAvPlayer；物理连续的输出缓冲映射到 GPU，按新时间戳复制 NV12 到持久纹理。CPU 不做 RGB 转换。主线程取得并保留 PCM，SDL 音频回调只读环形缓冲；播放器关闭前先解除回调。

## Logo 性能

旧路径每帧在 CPU 上重画 800×600 RGBA、逐像素混合三层，并上传 1,920,000 字节。60 fps 时光这一上传量就是 115.2 MB/s，还包含填充、混合和驱动等待；超过一帧预算就可能错过垂直同步。该代码是发现的主要性能瓶颈，不用它推断其他场景的帧率。

现在使用标准 MUL 和 ADD 两次混合实现每层 `D*(1-a*k)+S*a*k`，保持原贝塞尔轨迹、持续时间、三色及最终淡出。约 1.07 MB 的三个纹理仅上传一次；动画每帧更新位置和调制参数。快照记录相应绘制命令，需要快照时才在 CPU 合成。

全 64 变体、1,280 帧的内存对照：新旧最大差 5/255，平均 0.0218842/255；快照和 SDL 输出最大差 2/255。它有 8 位混合舍入差异，不能宣称逐像素一致。用户实机日志连续九段为 59.9–60.0 fps，提交平均 0.006–0.028 ms，逐帧上传 0。实机 Logo 掉帧问题已由该日志验证改善。

## 验证边界

生产代码 AVPlayer API 替身检查通过，覆盖高位指针、初始化失败、READY/缓冲状态、显式启动、PCM、暂停、EOF 和释放顺序。UI、输入、重启、特效及快照主机回归通过。隔离 Vita3K 在图形初始化发生宿主异常，未形成片头验收结果。片头全长音画同步、手动跳过、休眠恢复和长时间稳定性仍需实机验证。
